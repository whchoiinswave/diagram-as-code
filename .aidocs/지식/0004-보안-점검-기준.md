# KNOW-0004 보안 점검 기준

## 결정

의존성 취약점 점검은 `/Users/wanho/workspace/vibe/whchoiinswave/osv-check`를 기본 도구로 사용한다. 이 도구는 OSV API 기반으로 lockfile 또는 SBOM을 분석해 알려진 오픈소스 취약점을 찾는다.

GitHub URL `https://github.com/whchoiinswave/osv-check`는 문서 작성 시점에 외부에서 확인되지 않았다. 로컬 repo 기준으로 기능을 확인했다.

## 적용 범위

`osv-check`로 확인할 수 있는 항목:

- npm, PyPI, Maven, Go, Rust 의존성 취약점
- lockfile 기반 의존성 조회
- Syft SBOM 기반 의존성 조회
- severity 기준 필터링
- table, json, html 리포트

`osv-check`만으로 충분하지 않은 항목:

- 애플리케이션 코드의 보안 버그
- XSS, path traversal, 권한 검증 누락 같은 소스 코드 취약점
- secret/API key 유출
- 라이선스 정책 검증
- 컨테이너 이미지 런타임 설정 점검

## 실행 명령

diagram-as-code 프로젝트 루트에서 실행한다.

```bash
node ../osv-check/bin/osv-check.js . -e npm
```

HIGH 이상만 확인한다.

```bash
node ../osv-check/bin/osv-check.js . -e npm -s HIGH
```

JSON 리포트를 남긴다.

```bash
node ../osv-check/bin/osv-check.js . -e npm -f json -o .aidocs/임시/osv-report.json
```

HTML 리포트를 남긴다.

```bash
node ../osv-check/bin/osv-check.js . -e npm -f html -o .aidocs/임시/osv-report.html
```

Syft SBOM 기반 점검을 실행한다. 이 방식은 `syft` 설치가 필요하다.

```bash
node ../osv-check/bin/vuln-check.js . -s HIGH --sbom-output .aidocs/임시/sbom.json
```

## 보안 게이트

MVP 기준:

- `npm run build` 전후로 `osv-check`를 실행한다.
- `CRITICAL` 또는 `HIGH` 취약점이 있으면 릴리스하지 않는다.
- `MEDIUM`은 영향 범위와 exploit 가능성을 보고 TODO로 기록한다.
- 리포트는 `.aidocs/임시/`에 저장하고, 릴리스 판단에 사용한 요약은 관련 구현 문서의 `검증` 섹션에 기록한다.

협업/server 기능 도입 이후 추가 기준:

- server workspace provider에서 root path traversal 방지를 테스트한다.
- `LaunchContext`와 `DiagramTarget` payload는 `zod`로 검증한다.
- Mermaid render output은 unsafe script 실행을 막는 설정과 삽입 방식을 사용한다.
- Markdown block write-back은 target stale 상태를 확인한 뒤 수행한다.
