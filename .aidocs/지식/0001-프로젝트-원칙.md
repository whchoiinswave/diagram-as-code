# KNOW-0001 프로젝트 원칙

## 목표

프로젝트의 목표는 AI가 만들고 사람이 수정하기 쉬운 diagram-as-code 편집기를 만드는 것이다. 첫 지원 언어는 Mermaid로 시작하지만 제품 정체성은 Mermaid 전용 편집기가 아니라 diagram 편집기다.

## 핵심 원칙

- 텍스트 DSL을 원본으로 삼는다.
- 뷰어와 편집기는 항상 결합한다.
- 실시간 미리보기는 기본 경험이다.
- 렌더링 오류는 사용자가 고칠 수 있는 진단 정보로 보여준다.
- AI 기능은 생성보다 수정, 복구, 변환 흐름을 우선한다.
- Mermaid first, multi-dialect ready 구조로 간다.
- 기능은 문서, 요청, 할일, 구현 기록과 연결한다.

## 지원 우선순위

1. Mermaid: MVP 기본 DSL
2. D2: 범용 구조도와 시스템 다이어그램 확장 후보
3. PlantUML: UML 완성도가 필요한 경우 확장 후보
4. Graphviz DOT: 의존성 그래프와 코드 분석 결과 시각화 후보
5. Structurizr DSL: C4 모델과 아키텍처 문서화 후보
6. DBML: 데이터베이스 스키마와 ERD 후보

## 구현 방향성

에디터, 렌더러, 진단, AI 보조 기능을 분리한다. 초기에는 Mermaid 렌더러를 직접 붙이고, 이후 dialect adapter를 추가해 같은 편집 경험에서 여러 DSL을 다룰 수 있게 한다.

초기 라이브러리 결정은 [KNOW-0002 라이브러리 선정](./0002-라이브러리-선정.md)을 따른다.

```ts
type DiagramDialect = {
  id: string;
  label: string;
  detect: (source: string) => boolean;
  render: (source: string) => Promise<string>;
  validate?: (source: string) => Promise<Diagnostic[]>;
  format?: (source: string) => Promise<string>;
  aiHints: string;
};
```

## 초기 제품 범위

- 좌측 코드 편집기
- 우측 실시간 다이어그램 뷰어
- Mermaid 예제 템플릿
- 렌더 오류 표시
- SVG export
- Markdown fenced code block import/export
- AI 보조를 넣기 쉬운 내부 구조
