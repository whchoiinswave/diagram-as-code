# KNOW-0002 라이브러리 선정

## 결정

초기 구현은 `Vite + React + TypeScript + CodeMirror + Mermaid + Yjs + Hocuspocus` 조합으로 진행한다. Mermaid 전용 구조가 아니라 diagram dialect를 교체할 수 있는 편집기 구조를 유지한다.

## 채택 라이브러리

| 영역 | 라이브러리 | 단계 | 사용하는 이유 |
| --- | --- | --- | --- |
| 앱 빌드 | `vite` | MVP | React TypeScript 템플릿과 빠른 개발 서버, HMR, 정적 배포 구조가 단순하다. |
| UI | `react`, `react-dom` | MVP | 에디터, 뷰어, 패널, 모달, 협업 상태를 컴포넌트 단위로 나누기 쉽다. |
| 타입 | `typescript` | MVP | `DiagramDialect`, render state, collaboration state 같은 계약을 명확히 유지한다. |
| 코드 에디터 | `codemirror`, `@codemirror/state`, `@codemirror/view`, `@codemirror/commands`, `@codemirror/language` | MVP | 웹 코드 편집기에 필요한 문서 모델, 확장 시스템, selection, keymap, 대용량 텍스트 처리를 제공한다. |
| Markdown 보조 | `@codemirror/lang-markdown` | MVP | Markdown fenced code block import/export와 예제 문서 편집을 지원하기 쉽다. Mermaid 자체 문법 highlight는 이후 별도 확장으로 둔다. |
| 에디터 진단/자동완성/검색 | `@codemirror/lint`, `@codemirror/autocomplete`, `@codemirror/search` | MVP | 렌더 오류를 editor 진단으로 연결하고, snippet 자동완성, source 검색을 제공한다. |
| 다이어그램 렌더링 | `mermaid` | MVP | 첫 dialect renderer다. `render`로 SVG를 만들고 `parse`로 구문 검증을 할 수 있다. |
| 클라이언트 상태 | `zustand` | Workspace MVP | 선택 파일, tool mode, preview viewport, 저장 상태, 협업 상태 같은 UI 상태를 source와 분리해서 관리한다. |
| 패널 레이아웃 | `react-resizable-panels` | Workspace MVP | 좌측 파일 tree, editor/preview split, 우측 tool palette 패널을 사용자가 조절할 수 있게 한다. |
| 파일 트리 | `react-arborist` | Workspace MVP | 하위 폴더의 diagram 파일을 tree로 보여주고, 큰 workspace에서도 virtualized tree를 사용할 수 있다. |
| 도구 drag/drop | `@dnd-kit/core`, `@dnd-kit/modifiers` | Workspace MVP | tool palette 아이콘을 editor/preview 영역으로 drag/drop해 dialect별 snippet을 삽입한다. |
| Preview pan/zoom | `@panzoom/panzoom` | Workspace MVP | 큰 SVG/DOM preview에서 손모양 pan mode, zoom, reset, fit-to-screen 기반을 제공한다. |
| CRDT | `yjs` | 협업 MVP | 동시 편집 원본인 diagram source를 `Y.Text`로 관리하고 충돌 없이 병합한다. |
| CodeMirror 협업 바인딩 | `y-codemirror.next` | 협업 MVP | CodeMirror 6와 `Y.Text`를 연결하고 remote cursor, selection, collaborative undo 기반을 제공한다. |
| 협업 클라이언트 | `@hocuspocus/provider` | 협업 MVP | 브라우저에서 Hocuspocus WebSocket 서버에 연결하고 Yjs awareness를 운반한다. |
| 협업 서버 | `@hocuspocus/server` | 협업 MVP | Yjs sync, 인증, 권한, persistence hook을 서버에서 관리한다. |
| 서버 API | `hono`, `@hono/node-server` | 서버 협업 MVP | launch context, 파일 목록, target read/write 같은 HTTP API를 작고 타입 친화적인 서버로 제공한다. |
| 서버 파일 검색/감시 | `fast-glob`, `chokidar` | 서버 workspace MVP | storage root 하위의 관련 확장자 파일을 빠르게 찾고 외부 변경을 감지한다. |
| Markdown AST | `unified`, `remark-parse`, `remark-stringify`, `unist-util-visit` | 서버 협업 MVP | Markdown 내부 fenced diagram block을 구조적으로 찾고 수정한 뒤 원래 Markdown으로 직렬화한다. |
| 런타임 검증 | `zod` | 서버/클라이언트 MVP | `LaunchContext`, `DiagramTarget`, storage API payload를 런타임에서 검증한다. |
| 브라우저 오프라인 저장 | `y-indexeddb` | 협업 MVP 이후 | 탭 재시작과 오프라인 편집을 위해 Yjs document를 IndexedDB에 캐시한다. |
| 서버 로컬 저장 | `@hocuspocus/extension-sqlite` | 협업 MVP 이후 | 개발/소규모 배포에서 Yjs document binary를 파일 기반 SQLite에 저장한다. |
| 아이콘 | `lucide-react` | MVP | 툴바 버튼을 텍스트보다 익숙한 아이콘 중심으로 구성한다. |
| Diff 표시 | `diff` | AI MVP 이후 | AI proposal, Markdown block write-back 충돌, source 변경 preview를 unified diff로 보여준다. |
| 브라우저 폴더 접근 보조 | `browser-fs-access` | 선택 도입 | browser workspace provider를 먼저 구현할 경우 File System Access API와 legacy fallback을 감싼다. |
| 단위 테스트 | `vitest` | MVP | Vite와 잘 맞고 render adapter, parser, source transform 테스트를 빠르게 돌린다. |
| 컴포넌트 테스트 | `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`, `jsdom` | MVP | 에디터 주변 UI, 버튼, 템플릿 선택, 오류 표시를 사용자 동작 기준으로 검증한다. |
| E2E/시각 검증 | `@playwright/test` | MVP | 렌더링 결과가 비어 있지 않은지, 에디터/뷰어 레이아웃이 깨지지 않는지 브라우저에서 검증한다. |
| 코드 품질 | `eslint`, `typescript-eslint`, `prettier` | MVP | 타입/스타일 오류를 구현 초기에 고정한다. |
| 의존성 보안 점검 | `../osv-check` | MVP | lockfile 또는 Syft SBOM을 OSV API로 조회해 알려진 의존성 취약점을 릴리스 전에 차단한다. |

## 보류 라이브러리와 이유

| 라이브러리/방식 | 보류 이유 |
| --- | --- |
| `monaco-editor` | 강력하지만 초기 번들/워커/협업 연결이 CodeMirror보다 무겁다. VS Code급 기능이 필요해지면 재검토한다. |
| `y-websocket` | 단순 데모에는 좋지만 인증, 권한, persistence 훅을 직접 붙여야 한다. 협업을 제품 기능으로 볼 것이므로 Hocuspocus를 우선한다. |
| `automerge` | local-first 문서 모델에는 강하지만 코드 에디터 실시간 협업 생태계는 Yjs가 더 직접적이다. |
| `kroki` | 다중 dialect 렌더링에 유용하지만 MVP는 Mermaid를 직접 렌더링한다. D2, PlantUML, Graphviz를 붙이는 시점에 HTTP renderer로 검토한다. |
| `@dnd-kit/react` | 새 API 계열로 보이며 현재는 stable 사용 사례가 많은 `@dnd-kit/core`를 우선한다. |
| `@tanstack/react-virtual` | 직접 file tree를 구현할 때는 좋지만, 초기에는 tree 전용 기능을 가진 `react-arborist`를 우선한다. |
| Tailwind CSS | 초기 UI는 앱 전용 CSS로도 충분하다. 디자인 시스템 반복이 커지면 도입한다. |

## 협업 데이터 원칙

- 공유 원본은 `Y.Text('source')`다.
- `meta`, `settings`처럼 작은 공유 상태는 `Y.Map`으로 둔다.
- cursor, selection, 접속자 목록은 awareness로만 동기화하고 영구 저장하지 않는다.
- preview SVG, diagnostics, render status는 source에서 파생되는 값이므로 저장하지 않는다.
- AI 결과는 source에 바로 덮어쓰지 않고 proposal/diff로 만든 뒤 사용자가 적용한다.
