## 구현 내용

제품 SPEC에 세 가지 실행 모드를 추가했다.

- Embedded Editor Mode: 외부 사이트에 단일 diagram editor만 제공
- Workspace Editor Mode: storage root의 관련 파일을 좌측 tree로 탐색하고 우측 패널에서 편집
- Server Collaboration Mode: 서버 launch context로 특정 diagram target을 자동으로 열고 동시 편집

협업 기준을 추가했다.

- 협업 room의 단위는 `DiagramTarget`이다.
- 파일 전체 diagram과 Markdown 내부 fenced code block을 모두 target으로 다룬다.
- 서버는 `LaunchContext`로 workspace, target, room id를 전달한다.
- 하나의 room은 하나의 Yjs document를 가진다.
- preview, diagnostics는 저장하지 않고 source에서 파생한다.
- 원본 파일이 외부에서 바뀐 경우 `sourceHash` 또는 version으로 stale 상태를 감지한다.

MVP 작업 계획에는 다음 작업을 추가했다.

- Embedded Editor Mode API와 shell
- `StorageProvider`
- workspace storage root 입력/선택 UI
- 관련 확장자 file filter
- 좌측 파일 tree
- 마우스/키보드/화살표 버튼 파일 순회
- preview pan/zoom/fit-to-screen
- 우측 아이콘 tool palette
- drag/drop snippet 삽입
- LaunchContext parser
- 서버 지정 DiagramTarget 자동 열기
- file target과 Markdown block target room id 규칙
- server workspace storage provider
- Markdown block read/write back

## 검증

- SPEC에 제품 모드, storage 추상화, 협업 기준, server launch context가 추가되었다.
- 작업 계획에 storage root 입력/선택, 파일 tree, 파일 순회, pan/zoom, tool palette, server target launch 작업이 추가되었다.
- 요청, 구현, SPEC, 작업 계획이 서로 링크되어 있다.

## 남은 결정

- 첫 workspace storage provider를 브라우저 File System Access API로 할지 서버 workspace provider로 할지 결정해야 한다.
- Markdown diagram block 식별 방식을 line range, block index, explicit id 중 무엇으로 우선할지 결정해야 한다.
