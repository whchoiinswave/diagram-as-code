## 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| Mermaid render가 unsafe SVG/HTML을 만들 수 있음 | 렌더 결과 삽입 방식을 제한하고 보안 설정을 검토한다. |
| `y-codemirror.next` TypeScript 호환 문제가 생김 | CodeMirror transaction과 `Y.Text`를 직접 연결하는 fallback을 둔다. |
| 협업 서버가 정적 배포와 맞지 않음 | 단일 사용자 SPA와 협업 서버를 분리 가능한 구조로 둔다. |
| 렌더 오류 위치 정보가 불충분함 | 원문 오류 메시지를 보존하고 line/column은 가능한 경우에만 표시한다. |
| AI가 사용자의 동시 편집을 덮어씀 | AI 결과는 proposal로만 만들고 적용 시점에 최신 source 기준 diff를 다시 계산한다. |
| 브라우저가 임의 로컬 경로를 읽을 수 없음 | browser File System Access API, server workspace provider, desktop wrapper를 StorageProvider로 분리한다. |
| Markdown block의 위치가 외부 수정으로 바뀜 | block index와 line range만 믿지 않고 sourceHash/version으로 stale 상태를 감지한다. |
